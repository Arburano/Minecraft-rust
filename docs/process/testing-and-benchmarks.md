# Тести і бенчмарки

## Види тестів

| Вид | Де | Коли обов'язковий |
| --- | --- | --- |
| Юніт-тести | `#[cfg(test)]` у модулі | кожна публічна функція з логікою |
| Проптести (`proptest`) | `tests/` крейта | координати, палітра, світло, маски, злиття регіонів, серіалізація |
| Еталонні порівняння | `tests/` | оптимізована реалізація проти наївної (мешер, світло, gather) |
| Золоті файли | `tests/golden/` | формати диска і мережі, конвертація асетів |
| Інтеграційні | `crates/<bin>/tests/` | сервер + боти, рукостискання, моди |
| Сценарні тести модів | `engine-cli test` | кожен мод у `mods/` |
| Фазз | `fuzz/` (cargo-fuzz), пізніше | декодери мережі і диска |

## Бенчмарки

- `criterion` у `crates/<crate>/benches/`. CI перевіряє, що вони компілюються (`cargo bench --no-run`).
- Кожен бенчмарк відповідає рядку в [`performance-budgets.md`](performance-budgets.md); у назві або коментарі — посилання на цей рядок.
- Фіксований корпус даних: синтетичний рельєф з фіксованим seed (`research/bench` як відправна точка), пізніше — експорт реального світу.
- Результати етапу 0 і тестова машина записуються в `docs/research/`. VM з 2 vCPU дає шум ±30% — фінальні числа знімаються на bare-metal з фіксованою частотою (розкид ≤ 5%).
- Регресія > 10% на гарячому бенчмарку — блокер PR (автоматично, коли з'явиться стабільний раннер).

## Що потрібно від кожного PR

1. `cargo fmt --all --check`, `cargo clippy --workspace --all-targets`, `cargo test --workspace` — зелені.
2. Нова логіка — з тестами. Оптимізація — з бенчмарком до/після.
3. Змінився формат диска/мережі — оновлені золоті файли і версія формату.
4. Змінилась специфікація — оновлений документ у `docs/`.

## Без GPU

CI не має GPU. Код рендера розділяється на чисту логіку (кулінг, пакування, вибір шляху за можливостями) з юніт-тестами і тонкий шар wgpu. Тести з GPU позначаються `#[ignore]` і запускаються вручну/на окремому раннері.
