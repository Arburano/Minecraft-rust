# LOD

Крейт: `lod`. ADR: 0011 (світло на клієнті, LOD із сервера).

## Модель

- LOD n — секція 16³ вокселів, де воксель = 2ⁿ блоків. LOD n-секція покриває (16·2ⁿ)³ блоків.
- Воксель LOD — домінантний непрозорий стан у кубі 2ⁿ (з пріоритетом поверхневих блоків, щоб трава не ставала землею). Формат — та сама палітрова секція, тому мешер, gather і рендер ті самі.
- Кільця (clipmap) навколо гравця:

| Кільце | Дальність, чанків | Рівень |
| --- | --- | --- |
| L0 | 0–12 (повні дані; 8 на Low, 16 на High) | повні секції |
| L1 | 12–24 | LOD1 |
| L2 | 24–48 | LOD2 |
| L3 | 48–64 | LOD3 |

Для цілі 64 чанки досить LOD0–LOD3. Далі — опційно на High/Ultra.

## Звідки береться LOD

- **Сервер рахує і шле LOD** (PRD §14, № 1). Клієнт LOD сам не генерує: для цього йому потрібен seed світу, а seed дає чит на пошук руд.
- Сервер тримає LOD-піраміду для згенерованої частини світу (+≈ 14% обсягу). Після зміни блоку предки L1..L3 позначаються брудними і перераховуються пакетно в `PostTick`/фоні (ціль ≤ 1 мс сумарно на правку).
- Для незгенерованої частини світу сервер може віддати LOD з дешевої карти висот і біомів (див. worldgen.md), не генеруючи повні чанки.
- Поки LOD не прийшов — туман на межі дальності, без дір.

## Клієнт

- Дисковий кеш LOD (ключ: світ + позиція + рівень + версія вузла). Повторний вхід не качає заново.
- Мешинг LOD тим самим мешером (`mesh_lod` 0.6.4 — порівняти з даунсемплінг + `fast_mesh` у T1).
- Світло LOD — лише небо, запечене у вершину; блокове світло далеко не видно.
- Шви між кільцями — «спідниці» (вертикальні полоси вниз по краю). Ціль: 0 видимих дір з 8 ракурсів (скріншот-тест).
- Динамічні ефекти далеко (сезони, сніг) — параметри шейдера, не нова геометрія.

## Бюджет

LOD до 64 чанків ≈ 4 МБ мешів (×5 запас = 20 МБ) і ≈ 400 юнітів (оцінка, analysis §13.4). Повні дані далі 12–16 чанків не тримаємо: світло на 64 чанки саме по собі зайняло б 1,52 ГіБ.
