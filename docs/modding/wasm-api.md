# WASM API

Контракт: [`../../wit/engine-api.wit`](../../wit/engine-api.wit), пакет `engine:api@0.1.0` (чернетка; фіналізує задача T0-07). Перевірка синтаксису: `wasm-tools component wit wit/engine-api.wit`.

## Інтерфейси

| Інтерфейс | Напрям | Призначення |
| --- | --- | --- |
| `types` | спільний | позиції, стани, події, помилки |
| `world-access` | хост → гість (імпорт) | читання і пакетна зміна блоків свого регіону, `send-to` |
| `components` | імпорт | реєстрація мод-компонентів, пакетне читання/запис стану в хості |
| `host-log` | імпорт | лог з рівнями (обмежений за частотою) |
| `guest` | експорт мода | `init` (декларація систем і підписок), `on-events`, `run-system` |

## Правила дизайну API (обов'язкові для змін)

1. **Пакетність.** Жодна функція не працює з одним блоком чи однією сутністю, якщо її можна викликати для списку. Виклик компонента коштує ≈ 0,4 мкс; 1 000 окремих викликів — 0,5 мс, один пакет — ≈ 3 мкс.
2. **Ціль:** ≤ 1 мкс на диспетчеризацію хука, ≤ 5 нс на подію в пакеті.
3. **Стан у хості.** API не заохочує тримати світ у лінійній пам'яті мода.
4. **Регіон.** Усе, що читає чи змінює світ, діє в межах регіону; поза ним — `out-of-region` помилка, а не тиха заборона.
5. **Атомарність.** Зміни світу від одного виклику застосовуються разом або не застосовуються зовсім.
6. **Без глобального часу.** Мод отримує номер тіку від хоста; системний годинник недоступний (детермінізм тестів).

## Версіонування

- Semver пакета. Мінорна версія лише додає (нові функції, нові варіанти в кінець). Мажорна може ламати.
- Рушій підтримує поточну і попередню мажорну через адаптер-компонент.
- Будь-яка зміна `wit/engine-api.wit` — окремий PR з оновленням цього документа, `mod-sdk` і тестового мода; ламка зміна — з ADR.

## Майбутні інтерфейси (не в 0.1)

UI (віджети меню і HUD), рендер-проходи на WGSL (рівень 3), запити до глобальних сервісів (асинхронні), інтерфейси між модами (мод експортує свій WIT).
