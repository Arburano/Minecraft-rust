# T0-14 hardware evidence summary — 2026-11-19

## Machine and conditions

One laptop, two adapters (owner decision, [open question No. 12](../../open-questions.md)):
**ASUS TUF FX505DU**, AMD Ryzen 7 3750H, about 14 GiB usable RAM,
Windows 11 build 28000, bare metal.

- iGPU: **AMD Radeon RX Vega 10 Graphics** — OEM driver 27.20.1032.2
  (Vulkan driver 2.0.137, GL 4.6.13596 Core Profile 20.10.32).
- dGPU: **NVIDIA GeForce GTX 1660 Ti** — driver 555.97 (32.0.15.5597),
  Vulkan API 1.3.278, GL 4.6.0.
- Microsoft Basic Render Driver (DX12 index 2) is software; **not measured**.

The human confirmed before the matrix: AC power plugged in, Windows power
mode "Best performance", games/browsers/video closed, and the laptop was left
idle while the runs executed. All runs are release builds
(`CARGO_PROFILE_RELEASE_DEBUG=0` only strips debug symbols; opt-level, LTO and
codegen-units are the repository release profile), `--environment bare-metal`,
defaults 500,000 quads / 600 draws / 30 warmup + 120 measured frames,
1280×720 offscreen RGBA8. Every run rendered 184,960 nonblack pixels.

## Vulkan and adapter enumeration

- The 2026-11-18 probe saw no Vulkan adapters because
  `VK_LAYER_AMD_switchable_graphics` makes `vkEnumeratePhysicalDevices`
  return `INCOMPLETE` with zero devices. With
  `VK_LOADER_LAYERS_DISABLE=VK_LAYER_AMD_switchable_graphics` both GPUs
  enumerate; **no driver update or reboot was needed**. See
  [vulkaninfo-2026-11-19.txt](vulkaninfo-2026-11-19.txt) for both outputs.
- To expose the Vega 10 on GL, the human set NVIDIA Control Panel →
  Manage 3D settings → Program settings → "Integrated graphics" for
  `gpu-probe.exe` and `quad-bench.exe`; the ignored image test additionally
  needed the same preference for its own test executable
  (`HKCU\Software\Microsoft\DirectX\UserGpuPreferences`, `GpuPreference=1;`).
- That setting **reorders adapters**: the committed
  [laptop-probe-2026-11-19.json](laptop-probe-2026-11-19.json) (captured after
  the setting) shows Vulkan/DX12 0 = Vega 10, 1 = GTX 1660 Ti, GL 0 = Vega 10.
  The DX12/Vulkan runs and the GTX 1660 Ti GL runs were captured **before**
  the setting, when 0 = GTX 1660 Ti, 1 = Vega 10 and GL 0 = GTX 1660 Ti.
  Every run JSON records its actual adapter name and index; all were
  validated against their file names.
- `gpu-probe.exe` crashes at exit (segfault, exit 139) **after** writing
  complete, valid JSON while GL is on the Vega 10; reproduced twice, see
  [probe-crash-note-2026-11-19.txt](probe-crash-note-2026-11-19.txt).
  `quad-bench.exe` exits cleanly on every combination.

### B vs C on the same adapter/backend

Path C (per-instance) is faster than B (vertex pulling) on the Vega 10 on
every backend: ~32% less GPU time on DX12 (1.652 vs 2.417 ms p50), ~29% on
Vulkan, ~25% on GL. On the GTX 1660 Ti the two paths are within ~5% of each
other on all backends. B executes 3M vertex invocations vs C's 2M at the
default counts, which explains the Vega gap; the discrete GPU is not
vertex-bound at this workload. CPU recording is similar between paths
(within ~0.1 ms); DX12 records slower than Vulkan/GL on both adapters.
Both paths drew **identical nonblank images** on every adapter/backend
(image tests below), so the B/C choice remains a performance decision, not
a correctness one.

## Budget conclusions

- **GPU geometry ≤ 8 ms per frame on iGPU — met.** The engine would select
  path B on the Vega 10 (it has `VERTEX_STORAGE`): worst backend is GL at
  2.612 ms p50 / 2.821 ms p95; DX12 B is 2.417 / 2.619. Path C is also given
  above (1.637–1.948 ms p50). All ≤ 8 ms with ≥ 2.8× headroom.
- **CPU command recording ≤ 1 ms per frame — met.** Worst adapter/backend is
  Vega 10 on DX12: 0.535 ms p50, 0.821 ms p95 (median of runs); the worst
  single-run p95 anywhere is 0.923 ms. All ≤ 1 ms.
- **GTX 1050 targets remain unverified.** Per owner decision No. 12 there is
  no GTX 1050; the GTX 1660 Ti is considerably faster and its numbers do
  **not** verify the PRD "60 FPS on iGPU / GTX 1050" or stage 5 "64 chunks on
  GTX 1050" targets. Those stay unchanged and marked not verified.
- Both adapters share one CPU, RAM, OS and power envelope; this is one
  machine with two adapters, not two machines.

## Unsupported / unavailable combinations

- **GTX 1050 (any backend):** hardware not present (owner decision No. 12).
- **GTX 1660 Ti on GL while the "Integrated graphics" program setting is
  active:** GL then exposes only the Vega 10. The committed GTX 1660 Ti GL
  runs were captured before the setting; both configurations are documented
  above and in `research/gpu/run-matrix.cmd`.
- **Vulkan without the layer workaround:** enumeration returns `INCOMPLETE`
  with zero devices (AMD switchable-graphics layer); documented, not skipped.
- **Microsoft Basic Render Driver:** software adapter, deliberately not
  measured.
- No combination failed the image comparison or produced a blank frame.

## Review notes (2026-11-19)

Independent re-check of all 38 run JSONs reproduced the tables above. Two points
the tables do not show:

- **Single-frame CPU recording maxima exceed 1 ms** on the Vega 10 + DX12:
  1.323 ms (path B) and 1.061 ms (path C). The budget "≤ 1 ms per frame" names no
  statistic; it is judged at p95 here. Whether isolated frames above 1 ms are
  acceptable is part of [open question No. 14](../../open-questions.md).
- **Path selection vs measurement:** `select_path` picks B whenever
  `VERTEX_STORAGE` exists, but C is 25–32% faster on the iGPU on every backend.
  This is a synthetic corpus of unit quads with non-indexed B (6 vertices/quad);
  it is recorded as [open question No. 13](../../open-questions.md), not acted on.
